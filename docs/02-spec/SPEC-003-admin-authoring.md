# 後台寫作能力（3B）：表格、程式碼上色、Mermaid、圖片上傳、後台預覽

> 需求與任務拆解由 PM 於 2026-11-15 確認。這份 SPEC 是 3B 的主文件。
> 本專案目前沒有 3B 專屬 PRD，`related_prd` 暫掛在內容 runtime 的 PRD-001。

## 目標

- 文章與專案的 Markdown 內容可以放表格、有上色的程式碼區塊、Mermaid 圖表與圖片。
- 管理員可以在後台編輯頁直接上傳圖片，不必離開後台。
- 管理員發佈前可以在後台預覽，看到和前台相同的輸出結果。

## 非目標

- 圖片管理頁（清單、刪除舊圖）、拖拉或貼上上傳、圖片自動壓縮或裁切。
- 圖片下方的圖說文字（替代文字不顯示在畫面上）。
- 所見即所得編輯器、編輯器內的語法上色。
- 把 migration 套用到 production：由 reviewer 在 PM 同意後執行。
- 視覺改版（3C）與內容補完（3D）。

## 驗收條件

### 共用 Markdown 輸出

- [ ] 新增共用元件 `MarkdownContent`，文章內頁、專案內頁與後台預覽都用它輸出 Markdown；`Prose` 仍只負責排版樣式。
- [ ] 既有已上架的文章與專案，輸出結果除了新增的能力之外沒有改變。
- [ ] 不允許 Markdown 內的原始 HTML 被輸出成標籤（維持目前的安全行為）。

### 表格

- [ ] GFM 表格語法會輸出成 `<table>`，含表頭列；刪除線與待辦清單語法也一併支援。
- [ ] 表格比螢幕寬時，在表格自己的容器內左右捲動；頁面本身在 390px 寬度下不出現橫向捲軸。
- [ ] 表格文字與底色的對比不低於 4.5:1，樣式只用既有 design token。

### 程式碼上色

- [ ] 標了語言的程式碼區塊（例如 ```` ```ts ````）在伺服器端完成上色，讀者端不為了上色下載額外的 JavaScript。
- [ ] 沒標語言或語言不認得的區塊照常顯示成未上色的程式碼，不報錯。
- [ ] 上色後每種顏色與程式碼區塊底色的對比不低於 4.5:1。
- [ ] 程式碼過長時在區塊內左右捲動，不撐破版面。

### 程式碼區塊的複製按鈕與語言標籤

> 2026-11-15 PM 核准追加的範圍。

- [ ] 前台與後台預覽的每個程式碼區塊上方都有一列標頭：左邊是語言名稱，右邊是「複製」按鈕。
- [ ] 有標語言時顯示語言名稱：常見語言顯示正式名稱（例如 `ts` 顯示 `TypeScript`），其他語言照原本寫的名稱顯示；沒標語言時不顯示語言名稱，只有複製按鈕。
- [ ] 按「複製」會用 `navigator.clipboard.writeText` 複製區塊的原始程式碼：不含行號或標記，結尾不多一個換行。
- [ ] 複製成功後按鈕文字變成「已複製」約 2 秒，並讓螢幕閱讀器念出（`aria-live="polite"` 或同等做法）；剪貼簿失敗時顯示「複製失敗」，不丟出錯誤。
- [ ] 按鈕是真正的 `<button type="button">`：可以用鍵盤操作、有看得見的焦點框；手機上的可點範圍至少 44×44px（外觀可以較小）；文字與底色對比不低於 4.5:1；在 390px 寬的螢幕上不遮住程式碼。
- [ ] Mermaid 區塊沒有複製按鈕，也沒有語言標籤。
- [ ] 不顯示行號。
- [ ] 讀者端只多一個小的 client component；程式碼上色仍在伺服器端完成。樣式只用既有 design token。

### Mermaid

- [ ] 語言標為 `mermaid` 的區塊會顯示成圖表。
- [ ] 語法錯誤時，該區塊顯示原始碼加上一句提示「這張圖表的語法有誤，無法顯示。」，頁面其他內容照常顯示，不出現整頁錯誤。
- [ ] 內容裡沒有 mermaid 區塊的頁面，不下載 Mermaid 程式（以網路請求驗證）。
- [ ] Mermaid 以最嚴格的安全等級執行（`securityLevel: "strict"`），圖表內不能執行腳本或放可點擊的 HTML。
- [ ] 圖表比螢幕寬時在自己的容器內捲動；圖表載入前保留區塊，不讓版面大幅跳動。
- [ ] 關閉 JavaScript 或圖表尚未載入時，讀者看得到原始碼，而不是空白。

### 圖片儲存與上傳通道

- [ ] migration 建立公開讀取的 Storage bucket `content-images`：單檔上限 5MB（5,242,880 bytes），只允許 `image/png`、`image/jpeg`、`image/webp`、`image/gif`。migration 可重複執行不出錯。
- [ ] 沒有任何給 `anon` 或 `authenticated` 角色的寫入、更新、刪除政策；寫入只能透過伺服器發出的一次性上傳網址。
- [ ] 新增只接受 POST 的端點，回傳一次性上傳網址與之後的公開網址。端點依序檢查，任何一項不過都不發網址：
  - 未登入 → 401。
  - 已登入但不是允許的管理員 → 403。
  - 來源不是本站（沿用既有的 trusted origin 檢查）→ 403。
  - 檔案類型不是四種允許格式 → 400，訊息「只能上傳 PNG、JPG、WebP 或 GIF 圖片。」
  - 宣告的檔案大小超過 5MB、為 0 或不是數字 → 400，訊息「圖片不能超過 5MB。」
- [ ] 檔名由伺服器決定（隨機字串加上依檔案類型決定的副檔名），不使用使用者提供的檔名或路徑。
- [ ] 圖片檔本身不經過本站伺服器，由瀏覽器直接傳到 Supabase（避開 Vercel 4.5MB 的請求上限）。
- [ ] `SUPABASE_SERVICE_ROLE_KEY` 不出現在任何送到瀏覽器的程式或回應裡。

### 後台上傳介面

- [ ] 文章與專案的新增、編輯頁，內容欄位旁都有「上傳圖片」區塊：選檔、替代文字輸入框、上傳按鈕。
- [ ] 替代文字必填；沒填時不送出，顯示「請輸入圖片的替代文字。」
- [ ] 選到不允許的格式或超過 5MB 的檔案時，在送出前就顯示對應錯誤訊息。
- [ ] 上傳成功後，把 `![替代文字](公開網址)` 插入內容欄位目前游標位置（沒有游標時加在最後），並清空選檔與替代文字。
- [ ] 上傳中按鈕不可重複點擊並顯示進行中狀態；失敗時顯示原因，內容欄位已輸入的文字不受影響。
- [ ] 替代文字裡的 `[`、`]` 與換行會被處理，不會弄壞插入的 Markdown 語法。
- [ ] 專案表單有多個文字欄位時，圖片只插入 Markdown 內容欄位。

### 後台預覽

- [ ] 文章與專案的新增、編輯頁有「預覽」切換，顯示目前內容欄位（含尚未儲存的修改）用 `MarkdownContent` 輸出的結果，包含表格、上色、Mermaid 與圖片。
- [ ] 預覽不會儲存、不會發佈，也不會改變表單內容；切回編輯時文字與游標所在欄位的內容不變。
- [ ] 預覽只有通過管理員檢查的人看得到。

### 公開頁面的圖片

- [ ] Markdown 裡的圖片輸出時帶 `loading="lazy"` 與 `decoding="async"`，寬度不超過內容欄。
- [ ] 圖片網址可以是 `content-images` bucket 的公開網址，也可以是其他 https 網址；不因此需要改 `next.config.ts`。

## 測試方式

- 單元測試（Node test runner）：端點的每一個拒絕情境與成功情境、檔名產生、替代文字處理、插入位置、Markdown 輸出（表格、上色、mermaid 區塊辨識、原始 HTML 不輸出）。
- Reviewer 以本機正式版 build 加測試內容，檢查 1440×900 與 390×844 兩種寬度的對比、橫向捲動、console 錯誤與 Mermaid 的網路請求。
- 真正上傳一張圖到 production bucket：需要管理員登入，由 PM 在上線後驗證。

## 已知限制

- 換掉或不再使用的圖片會留在 bucket，沒有清理機制。
- Supabase 只檢查上傳時宣告的檔案類型，不檢查檔案實際內容；因為只有管理員能取得上傳網址，且不允許 SVG，風險可接受。
