# 視覺改版（3C）：兩欄身分區、分頁導覽、赤陶重點色、小圓角

> 需求與任務拆解由 PM 於 2026-11-16 確認。設計方向與規則見根目錄 [DESIGN.md](../../DESIGN.md)；本文件是實作規格與驗收條件。
> 本專案目前沒有 3C 專屬 PRD，`related_prd` 暫掛在內容 runtime 的 PRD-001。
> 這份規格取代 SPEC-002 的兩項決定：首頁五段的排列方式（內容不變，改為左欄加分頁），以及文章日期只顯示年月（改為顯示到日）。

## 目標

- 讀者一進首頁就知道「這是誰」，並看得到案例；往下捲時身分區仍留在畫面上。
- 案例與文章一眼分得出來，數量變多也不混淆。
- 版面在內容很少時也成立。
- 視覺收斂：一個重點色、小圓角、不靠裝飾。

## 非目標

- 後台頁面（`/admin/*`）的樣式。
- 社群分享圖（`opengraph-image.tsx`，沿用自己內建的字體）。
- 案例、文章與 About 的文字內容（3D）。
- 深色模式。
- 資料模型與後台功能。

## 驗收條件

### 版面結構

- [ ] `/`（首頁）與 `/blog`（文章列表）在 `lg` 以上是兩欄：左欄身分區，右欄是分頁與清單。左欄捲動時固定在畫面上（sticky），高度超過視窗時不會遮住內容或無法捲到底。
- [ ] 身分區內容，兩頁完全相同：頭像、姓名、職稱 `Product Manager / Product Builder`、定位句「我把模糊的需求整理成可以上線的產品，並用 AI 把想法更快做成成果。」、簡介「我從教育現場、BD 與產品規劃，一路走到產品經理。現在是 AI 產品經理，協助公司進行組織 AI 化。」、主要按鈕「更多關於我」（到 `/about`）、次要按鈕「寫信給我」（既有的 mailto）。不提目前公司名稱或產業，不寫「開放工作機會」。
- [ ] 右欄最上方是分頁：「案例 N」連到 `/`，「文章 N」連到 `/blog`。N 是實際已上架的數量。目前所在的分頁有 `aria-current="page"` 與赤陶底線。分頁是一般連結（不是 JavaScript 切換），沒有 JavaScript 也能用。
- [ ] 首頁顯示全部已上架案例：`featured` 的排前面，其餘照既有排序。每個案例是細外框區塊，含類型標籤、角色、期間、標題、摘要、第一條成果（有才顯示）。清單最下方有連到 `/blog` 的「也看看我寫的文章」。
- [ ] `/blog` 顯示全部已上架文章，細線分隔，每篇含完整日期、標題、摘要（有才顯示）。清單最下方有連到 `/` 的「回到案例」。
- [ ] 沒有任何已上架案例或文章時，該分頁顯示一句說明文字，分頁數字為 0，版面不壞。只有 1 筆時版面正常。
- [ ] `lg` 以下是單欄：身分區在上，分頁與清單在下。390px 寬沒有整頁橫向捲動。
- [ ] 首頁第一個畫面（1440×900）同時看得到頭像、姓名、職稱、定位句、分頁標籤與至少一個案例。
- [ ] 案例內頁、文章內頁、About、404 維持單欄，套用新 token。
- [ ] 每頁一個 H1，標題層級不跳號。首頁的 H1 是定位句；`/blog` 的 H1 是「文章」相關的頁面標題（可以只給螢幕閱讀器），定位句在該頁不是 H1。

### 導覽與網址

- [ ] 頁首選單只留 About；左上角站名連到 `/`。登入的管理員仍看得到「後台」與「登出」。手機選單同步調整（項目少到不需要收合時，直接顯示，不保留 Menu 按鈕）。
- [ ] `/projects` 以永久轉址（308）轉到 `/`。`/projects/[slug]` 內頁網址與內容不變。
- [ ] 站內原本連到 `/projects` 的連結（頁尾、內頁的返回連結、404、後台的「查看前台」之類）改為連到 `/`，文字改成「案例」。
- [ ] `sitemap.xml` 不再列 `/projects`；其餘公開頁照常列出。
- [ ] 頁尾精簡，不重複頁首已有的導覽；保留姓名與 email。

### 視覺

- [ ] 重點色赤陶 `#A8452B` 定義成 token，全站彩色只有它，且只出現在：類型標籤文字、目前分頁的底線、hover 時標題的底線、案例內頁成果清單左側的線、鍵盤焦點外框。主要按鈕是黑底白字（主要文字色）。
- [ ] 程式碼上色的 `--code-*` 色票是內容的一部分，不算在「只有一個彩色」的限制內；它們與新的程式碼區塊底色對比仍 ≥ 4.5:1。
- [ ] 圓角 token 收小：一般元件 6px、區塊與圖片 8px。公開頁不再有膠囊形按鈕與大圓角。頭像維持圓形。
- [ ] 標題改用系統字體（與內文相同）。`layout.tsx` 不再載入 Noto Serif TC；公開頁面不再請求該字體檔。`opengraph-image.tsx` 與它用的字體檔不動。
- [ ] 拿掉頁首的 `backdrop-blur` 與半透明底、頁面背景的漸層光暈。浮層（同意橫幅）可保留陰影。
- [ ] 公開頁不寫死色碼、圓角、字級；缺的 token 補在 `globals.css` 並更新 `docs/design-tokens.md`。
- [ ] 可互動元件都有一般、hover、鍵盤焦點狀態；焦點外框看得見。

### 日期

- [ ] 文章卡片、文章內頁、案例內頁的延伸閱讀，日期顯示成 `2026 年 6 月 12 日`，以台北時間（`Asia/Taipei`）判斷日期：`2026-06-11T20:14:20Z` → `2026 年 6 月 12 日`；`2026-06-12T15:59:59Z` → `2026 年 6 月 12 日`；`2026-06-12T16:00:00Z` → `2026 年 6 月 13 日`。
- [ ] `<time>` 的 `dateTime` 屬性仍是完整的機器可讀時間。
- [ ] 案例的「期間」維持後台填寫的文字，不轉換。

### 品質

- [ ] 文字與背景對比 ≥ 4.5:1（大字 ≥ 3:1）。
- [ ] 手機上可點元素高度 ≥ 44px。
- [ ] 鍵盤 Tab 走得到每個可點元素。
- [ ] console 沒有錯誤；沒有整頁橫向捲動（1440×900 與 390×844）。
- [ ] 既有的 metadata、OG、canonical、robots 行為不變；首頁與 `/blog` 的 title、description 維持現有文字。
- [ ] PostHog 的 pageview 事件屬性（contentType、sourceTemplate）維持現有值。
- [ ] `npm test` 全過、`npm run lint` 0 錯誤、`npx tsc --noEmit` 錯誤數不高於 main、`npm run build` 成功。

## 測試方式

- 單元測試：首頁資料排序（featured 在前）、分頁數量、空狀態、日期格式與時區邊界、轉址設定、sitemap 內容、元件的標題層級與 `aria-current`。
- Reviewer 以本機正式版 build 跑全站稽核（對比、點擊區、標題層級、橫向捲動、console），並截每一頁的電腦版與手機版給 PM 確認。

## 已知限制

- 左欄身分區在 `/` 與 `/blog` 重複出現，手機上讀者到 `/blog` 要先捲過身分區才看到文章。若 PM 覺得太長，再另外討論在 `/blog` 的手機版收合身分區。
