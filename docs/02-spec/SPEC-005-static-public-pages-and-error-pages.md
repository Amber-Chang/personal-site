# 公開頁預先產生與錯誤頁（架構檢視 F2、F3）

> 需求與任務拆解由 PM 於 2026-11-17 確認。背景見架構檢視：F2「網站完全依賴 Supabase 即時回應」、F3「出錯時只有一行英文錯誤」。
> 本專案目前沒有專屬 PRD，`related_prd` 暫掛在內容 runtime 的 PRD-001。

## 背景

- 公開頁都設定 `revalidate = 0`，而且根版面的 `Header` 每頁都呼叫 `cookies()` 讀管理員狀態，整站因此都是動態頁，正式站回應 `cache-control: private, no-store`。每次瀏覽都查一次 Supabase。
- 後台變更時呼叫的 `revalidatePath` 因為沒有快取可清，實際上沒有作用。
- 專案沒有 `error.tsx`、`global-error.tsx`。Supabase 暫停時讀者看到 Next.js 的英文「Application error」。Markdown 備援只在環境變數缺少時啟用，不處理 Supabase 停擺。

## 目標

- 讀者看到的公開頁是預先產生的頁面；Supabase 暫停或變慢時，讀者仍看得到最後一版。
- 管理員在後台做任何變更後，下一位讀者就看到新內容。
- 真的出錯時，讀者看到符合網站樣式、有說明與聯絡方式的錯誤頁。

## 非目標

- 後台頁面的快取（`/admin/*` 維持每次即時讀取）。
- 圖片最佳化（F7）、錯誤通知（F8）、預覽環境（F4）。
- 資料庫結構、登入流程、權限規則的變更。
- 改變任何公開頁的畫面、文案、metadata 或分析事件。

## 驗收條件

### 頁首的管理員入口（PM 決定保留，改成載入後判斷）

- [ ] 根版面與 `Header` 在伺服器渲染時不再讀 cookie 或登入狀態，不會因此讓頁面變成動態頁。
- [ ] 新增只回答「目前是否為允許的管理員」的端點（只接受 GET，回應 `cache-control: no-store`，不回傳 email 或其他個資）。允許清單仍只在伺服器端判斷。
- [ ] 頁首的「後台」「登出」改由瀏覽器端元件顯示：只有瀏覽器帶著 Supabase 登入 cookie 時才呼叫上述端點；沒有登入 cookie 的讀者不送出任何額外請求。
- [ ] 管理員登入時，頁首顯示「後台」（連到 `/admin/posts`）與「登出」；登出照常運作（沿用既有的 server action）。顯示前後頁首高度不跳動。
- [ ] 端點失敗或回應不是管理員時，頁首只顯示 About，不顯示錯誤。

### 公開頁預先產生

- [ ] `/`、`/blog`、`/blog/[slug]`、`/projects/[slug]`、`/about`、404 在 build 結果中不再是每次請求產生的動態頁（`ƒ`）。
- [ ] 部署時預先產生所有已上架的文章與案例內頁；之後新上架的內容在第一次瀏覽時產生並保存；不存在或未上架的網址回 404。
- [ ] 保險機制：公開頁每小時自動更新一次（處理不經過後台的資料變更）。
- [ ] 後台的每一種內容變更（文章與案例的新增、修改、發佈、取消發佈、刪除、排序）都會讓全站公開頁與 `sitemap.xml` 立即標記為需要更新；下一次瀏覽看到新內容，取消發佈或刪除的內頁變成 404。
- [ ] 更新時 Supabase 無法連線：已產生過的頁面繼續提供上一版，不顯示錯誤。
- [ ] 本機正式版同一頁連續瀏覽，第二次起直接使用快取（以回應標頭或 Supabase 請求次數驗證）。
- [ ] 環境變數缺少時的 Markdown 備援行為不變。
- [ ] 公開頁的 title、description、OG、canonical、robots 與 PostHog pageview 屬性和改動前相同。

### 錯誤頁

- [ ] 新增一般錯誤頁與最後防線錯誤頁（根版面也壞掉時使用）。兩者都不顯示錯誤訊息或技術細節。
- [ ] 文案（PM 已確認）：
  - 標題：「這個頁面暫時無法顯示」
  - 說明：「可能是網站正在維護，請稍後再試。如果急著找我，可以直接寫信到 taco5239@gmail.com。」
  - 按鈕：「重新整理」（重新嘗試載入）、「回首頁」
- [ ] email 以可選取的文字顯示，並附 mailto 連結。
- [ ] 套用現有 design token 與 `DESIGN.md` 的規則；每頁一個 H1；對比 ≥ 4.5:1；手機可點元素 ≥ 44px；390px 寬沒有橫向捲動。
- [ ] 最後防線錯誤頁不依賴根版面，自己帶完整的 `<html>`、`<body>` 與必要樣式。

### 品質

- [ ] `npm test` 全過、`npm run lint` 0 錯誤、`npx tsc --noEmit` 錯誤數不高於 main、`npm run build` 成功。
- [ ] 上線後在正式站確認公開頁有快取命中、管理員頁首正常。

## 測試方式

- 單元測試：管理員狀態端點的各種情況、頁首元件只在有登入 cookie 時才呼叫端點、後台每個變更動作都觸發全站更新、公開頁不再有 `revalidate = 0`、錯誤頁文案與結構。
- 本機正式版搭配本機假的 Supabase：快取命中、後台變更後更新、Supabase 停擺時提供上一版、從未產生過的頁面顯示錯誤頁。
- Reviewer 全站稽核與錯誤頁截圖，交 PM 確認。

## 已知限制

- 部署時需要連得到 Supabase；若部署當下 Supabase 暫停，該次部署失敗，正式站維持上一版。
- 不經過後台的資料變更（直接改資料庫、匯入腳本），最慢一小時後才反映到前台。
- 管理員登入時，頁首的「後台」「登出」會在頁面載入後才出現。
- 後台改完內容後、某一頁被下一位讀者打開之前，若 Supabase 剛好斷線，這一頁沒有上一版可以給，會回 500 錯誤，直到 Supabase 恢復；每小時的自動更新不受影響，仍會繼續提供上一版。目前本機看到的是一行英文「Internal Server Error」，不是新的錯誤頁；正式站的畫面要上線後確認。
