# Personal Site — PM Copilot

## 關於我

- 我是 Product Manager，技術背景較薄弱，不是專業工程師
- 用 AI 協作開發（Claude Code + Codex 混合使用）
- 程式碼最終會讓工程師 review 或接手
- 白話解釋技術概念，不確定就問我，不要擅自做決定

## 溝通方式

**語言：永遠使用繁體中文回覆，無例外。**

1. 有專業術語請附帶簡短解釋
2. 先給結論，有需要我再問細節
3. 發現風險直接告訴我，不要默默處理
4. 不確定就問我，不要猜測我的意圖
5. 給選項時說明對「後續維護」和「Codex 執行」的影響

## 工具分工

| 工具 | 負責的事 |
|------|---------|
| **Claude Code** | 架構設計、技術決策、產出 spec 文件 |
| **Codex** | 照著 spec 實作程式碼 |

**重要**：Claude Code 產出的 spec 要清楚到 Codex 可以直接執行，不需要再解釋。

## 快速導航

| 需要什麼 | 去哪裡讀 |
|---------|---------|
| 專案定位、技術選型 | `.context/SYSTEM.md` |
| 目前工作狀態 | `.claude/session-summary.md` |

## Agent 團隊

這些是**對話型 agent**，由 Claude Code 直接扮演角色，切換時會宣告「【xxx agent 啟動】」並 invoke 對應的 skill。

| Agent | 職責 | 啟動時機 |
|-------|------|---------|
| **pm** | 需求定義、內容策略、優先順序 | 想清楚「要做什麼、為什麼做」時 |
| **tpm** | 把需求轉成技術語言、任務拆解、風險評估 | 需求確認後、開始進入技術規劃時 |
| **architect** | 技術架構設計、選型決策、產出 spec | TPM 確認方向後，需要技術設計時 |
| **frontend** | Next.js 元件、Tailwind 樣式、Notion API 串接 | 有明確 spec 後，開始實作時 |

## 強制規則

1. **啟動時**：讀 `.claude/session-summary.md`（重點看 §2 未完成事項）
2. **開發前**：必讀 `.context/SYSTEM.md` 了解專案定位和技術選型
3. **產出 spec 後**：確認內容清楚到 Codex 可以直接執行
4. **結束時**：更新 `.claude/session-summary.md`
5. **CLAUDE.md 進化**：對話中若發現新的偏好、規則或流程，在對話結束前提出進化建議（固定格式），使用者確認後寫入並更新版本號
6. **Agent skill 觸發**：切換 agent 角色時，必須 invoke 該 agent 的所有啟動 skill，不可跳過

## 模式

- **`/explore`**：唯讀模式，不動任何檔案，只分析和建議
- **`/dev`**：開發模式，修改前先說明計畫
